# TradeSphere — Stock Trading Platform (microservices)

React + Tailwind frontend, Spring Boot microservices, Kafka, Redis, MySQL behind ProxySQL, and a full
OpenTelemetry → Grafana observability stack. **One command runs everything:**

```bash
docker compose up -d --build        # first build takes several minutes (Maven + npm + image pulls)
docker compose ps                   # wait until the apps are "healthy" (~1–2 min after build)
```

Login at **http://localhost:3000** with **`admin@example.com` / `password123`** (seeded, password stored as a BCrypt hash).

## Architecture

```
 Browser ─► nginx (frontend :3000) ──/api, /ws──► api-gateway :8080 (JWT check, adds X-User-Id)
                                                   ├─► user-service      ─┐
                                                   ├─► market-data-service ─► Redis (price cache) + Kafka + STOMP/WebSocket
                                                   ├─► order-service ─► user-service (Feign) · ai-service (fraud, Python) · Kafka
                                                   └─► portfolio-service ◄─ Kafka (order.executed)      notification-service ◄─ Kafka
   user/order/portfolio services ──► ProxySQL :6033 (pooling/multiplexing) ──► MySQL

 OpenTelemetry: every service ──OTLP──► otel-collector ─► Tempo (traces) · Loki (logs) · :8889 ◄─ Prometheus (metrics)
 Exporters → Prometheus: cAdvisor (containers) · node-exporter (host) · mysqld-exporter · ProxySQL (built-in) ·
                         redis-exporter · kafka-exporter + Kafka JMX agent · blackbox (uptime probes)
 Grafana: datasources + 5 dashboards + e-mail alert rules are all provisioned from ./observability
```

## Observability

**Traces / context propagation.** The OTel Java agent (auto) + Python `opentelemetry-instrument` propagate W3C
`traceparent` across gateway → services → Feign → Python AI service and through Kafka message headers, so one
order is a single trace: `gateway → order.place → user-service (deduct) → ai-service → Kafka → portfolio/notification`.
Manual instrumentation (OpenTelemetry API) adds the `order.place`/`user.login` spans, span attributes, and business metrics.

**Logs → traces.** Logs are shipped over OTLP with `trace_id`/`span_id`. In Grafana → Explore → Loki
(`{service_name="order-service"}`) expand a line and click **“Open trace in Tempo”**; from a span use **Logs for this span**.

**Dashboards** (folder *Trading Platform*): Services Overview (home) · Kafka · MySQL · ProxySQL · Redis.
The Services dashboard has uptime, p50/p95/p99 latency, availability + latency SLI vs SLO, error budget & burn rate,
successful/failed request totals, business KPIs (orders, value traded, logins, fraud checks…), container + node CPU/memory
with the 40 % threshold, JVM, logs and error traces. Dashboards are generated by `observability/tools/gen_*.py`
(`cd observability/tools && for f in gen_*.py; do python3 $f; done`).

**Alerting.** Grafana-managed rules fire when container or node **CPU / memory exceeds 40 %** (`for: 2m`) and send e-mail
through the SMTP block in `grafana.ini`. By default SMTP points at the bundled Mailpit — open http://localhost:8025.
For a real mailbox edit `.env` (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_STARTTLS_POLICY`, `ALERT_EMAIL_TO`) and
`docker compose up -d grafana`. Thresholds: `ALERT_CPU_THRESHOLD` / `ALERT_MEM_THRESHOLD`.
Quick test: Grafana → Alerting → Contact points → *email-oncall* → **Test**.
> JVM containers legitimately sit at 40–70 % of their memory limit, so expect the memory alert to fire. Raise the limits in
> `docker-compose.yml` or the threshold in `.env` if that is too noisy.

## Changes made to the existing code (please review)

* **`notification-service`**: fixed a compile error — `import lombok.extern.Slf4j` → `lombok.extern.slf4j.Slf4j`.
* **`market-data-service`**: `RedisConfig` now uses a Jackson mapper with the `java.time` module. The default serializer cannot write
  `LocalDateTime`, which would have broken the price scheduler on its first tick.
* **`api-gateway`**: service URLs / JWT secret are env-driven; WebSocket route uses `http://` (required for SockJS' HTTP calls).
* **All services**: DB/Kafka/Redis/service URLs read from env with the old localhost values as defaults, so `mvn spring-boot:run` still works.
  In Docker `JPA_DDL_AUTO=none` — the schema comes from `docker/mysql/init/02-schema.sql`.
* **`order-service`**: explicit `flagged_by_ai` column name (Spring's default would be `flagged_byai`); longer reason columns.
* **`user-service`**: `GlobalExceptionHandler` + `ApiException` → proper 401 (bad login), 409 (duplicate e-mail), 422 (insufficient funds), 404, 400
  instead of generic 500s; login no longer reveals whether an e-mail exists.
* **`ai-service`**: API key read from `ANTHROPIC_API_KEY` (was a hard-coded placeholder); rule-based fallback when unset; tolerates ```json fences.
* OpenTelemetry API/annotations dependencies + `telemetry/*Metrics` classes in each Java service.

## Known limitations / things you should know

* **ProxySQL load balancing:** there is one MySQL backend, so ProxySQL provides pooling, multiplexing, health-checking and metrics, but
  nothing to *balance between*. I did not add a read replica on purpose: replication lag would break read-your-writes here
  (register → immediate login, order → order list). To add one: new MySQL replica, an `mysql_replication_hostgroups` entry, hostgroup 10, and a `^SELECT` rule.
* **Pre-existing business-logic issues (not changed):** `SELL` does not verify the user owns the shares server-side (the UI blocks it, the API does not);
  `/users/{id}/funds/add|deduct|credit` are reachable by any authenticated user for any id (the UI only calls it for the logged-in user).
* **ProxySQL "transaction latency"** is not exported by ProxySQL; the dashboard shows backend query latency and says so.
* cAdvisor needs a Linux Docker host for full per-container metrics (Docker Desktop shows fewer).
* Compose uses fixed dev credentials (also in `docker/mysql/init/01-*.sql` and `proxysql.cnf`) — change all three together.

## Local development without Docker

`mvn spring-boot:run` per service with local MySQL/Kafka/Redis (defaults unchanged), `cd frontend && npm install && npm run dev` (proxies to :8080).
